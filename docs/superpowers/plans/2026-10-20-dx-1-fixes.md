# agent-forge DX — Sub-project 1: Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The herdr popup gets out of the way on success, and a half-provisioned container is recovered from `forge` itself, with no raw `incus` command.

**Architecture:**
- **Popup.** `cli/forge.ts` stops holding the popup open for warnings. A new module `cli/lib/popup.ts` collects the run's `WARNING`/`NOTICE` lines and `ctx.notify` lines; at the end of a successful popup run they become one herdr notification (`showNotification` in `cli/lib/herdr.ts`). Errors and non-zero exits still wait for Enter. `Context.attention()` is replaced by `Context.notify(line)`.
- **Half-provisioned container.** `provisionContainer` launches the container with two marker keys and removes them once `user.forge.repo` is written. `checkNameCollision` reports a half-provisioned container instead of throwing; `forge start` offers to recreate it and `forge delete` removes it. `discardHalfProvisioned` (in `provision.ts`) deletes the instance and, only when the failed attempt created the workspace, empties it.

**Tech Stack:** Node 24 (type stripping, `node --test`), TypeScript (`npm run check`), Incus 7.0, herdr 0.9.5.

**Spec:** `docs/superpowers/specs/2026-10-20-dx-chapter-design.md`, section "Sub-project 1: fixes" (and "Decisions"). Read it first.

## Global Constraints

- Code comments follow the file they are in (French in most of `cli/`, English in `herdr.ts` and the tests that are in English).
- No personal value (login, host, path, identity) in code, tests or docs.
- Every mutating `incus`/`git` call goes through `mustSucceed`; probes never do.
- The workspace and the mirror survive `forge delete` and a recreate. A workspace that existed before the failed provisioning is never removed.
- Outside the popup (a terminal, a herdr pane), the output of every command is unchanged, except for the removed retrieval hint.
- Commits: conventional messages (`feat:`, `fix:`, `test:`, `docs:`). The maintainer signs commits with a YubiKey; if they are not present, stop before committing and ask.

## Review Focus

1. **A popup run that both warns and fails** (a WARNING, then an exception): the user must see the error and wait for Enter; no notification replaces the error. → Task 3, test `an error after a warning in the popup still waits, without a notification`.
2. **A herdr notification that hangs or fails** (`notification show` exits non-zero): the warnings must not be lost: forge falls back to "Press Enter to close". → Task 3, test `when the notification fails, the popup falls back to waiting for Enter`.
3. **A recreate answered with no TTY** (popup closed, script): nothing is deleted, and the message names `forge delete <owner/repo>`. → Task 5, test `with no TTY, a half-provisioned container is left alone and the way out is named`.
4. **A half-provisioned container whose workspace was reused from an earlier `forge delete`**: its contents (the only copy of unretrieved work) survive the recreate. → Task 5, test `discarding keeps a workspace the failed attempt reused`.
5. **A marker naming another repository** (two repos sanitising to the same container name): still a collision, never a recreate. → Task 5, test `a provisioning marker for another repo is a collision`.
